# Задача для Deep Research: Архитектура Мульти-Агентных Систем (2026)

## Контекст
Мы разрабатываем образовательного AI-агента "NetRunner" для подготовки специалистов по ML/DL и алгоритмам.
Мы внедряем архитектуру **"Shared Memory + Specialized Subgraphs"** (Supervisor Pattern).

## Цель исследования
Найти технические детали реализации взаимодействия между **Subgraphs** в LangGraph (или аналогах) в 2026 году.

## Ключевые вопросы (Update)
1.  **State Schema Strategy**: Что лучше для сложного агента:
    *   **Monolithic State**: Один огромный TypedDict со всеми возможными полями (`quiz_data`, `algo_data`, `chat_history`).
    *   **Scoped State**: Разные схемы для разных подграфов с явным маппингом при переходе. Как это реализуется в коде?
2.  **Tool Isolation**: Как архитектурно запретить "Болталке" вызывать инструменты "Оценки квиза"? (Configurable tools vs Separate Graphs).
3.  **Handoff Patterns**: Как правильно вернуть управление от `QuizGraph` обратно `Supervisor`? Нужно ли использовать специальные "Handoff Tools" или это делается через `Command(goto=...)`?
4.  **Memory Persistence**: Как сохранять состояние квиза (Checkpointing), если пользователь ушел в "Болталку" и вернулся через день? Будет ли `QuizGraph` восстановлен из того же чекпоинта или нужно переносить данные в глобальный стейт?

## Ожидаемый результат
Примеры кода или архитектурные диаграммы, показывающие поток данных между `Supervisor` -> `SubGraph A` -> `Supervisor` -> `SubGraph B`.
