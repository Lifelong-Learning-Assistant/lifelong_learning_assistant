# Lifelong Learning Assistant для Deep Learning

> **Идея**: Создать персонализированного ИИ-ассистента для непрерывного обучения.

## 🎯 Цель проекта

Создать интеллектуального ассистента, который интегрирует личную базу знаний (Obsidian), внешние источники (учебники, статьи, новости) и помогает:

- **Непрерывно учиться** и адаптировать объяснения под текущий уровень понимания
- **Поддерживать актуальность** знаний через отслеживание трендов
- **Готовиться к собеседованиям** с контекстуальными ссылками
- **Вести персональную базу знаний** с автоматической поддержкой в актуальном состоянии

## 🧠 Архитектура системы

### Ключевые компоненты

| Компонент | Технологии | Основные функции |
|-----------|------------|------------------|
| **Сервис Агента** | FastAPI, LangGraph | Основной оркестратор, управление сессиями и логикой ИИ-агента. |
| **RAG Сервис** | Qdrant, Redis | Гибридный и семантический поиск по базе знаний (Учебник Яндекса по ML). |
| **Генератор Тестов** | FastAPI, LLM | Автоматическая генерация вопросов и оценка ответов на основе материалов. |
| **User Service** | PostgreSQL, JWT | Управление пользователями, аутентификация и хранение настроек. |
| **Web UI Service** | React, Tailwind v4 | Футуристичный интерфейс «Нетраннерская Дека» с WebSocket-чатом. |

### Функциональные возможности

- **🧠 Умный Ассистент**: объяснения сложных тем ML/DL с учетом контекста.
- **🧩 Интерактивные Квизы**: Динамическая генерация тестов для проверки знаний в режиме реального времени.
- **🔍 Глубокий Поиск (RAG)**: Ответы с опорой на верифицированные источники (Учебник Яндекса по ML).
- **🎭 Персонализация**: Выбор визуального аватара из 8 профессиональных ролей для кастомизации профиля.
- **💻 AlgoLab**: Симулятор собеседования по алгоритмам с интегрированной IDE и анализом сложности.

## 🛠 Техническая реализация

- **Frontend**: React 18, Vite, Tailwind CSS v4, Framer Motion (HUD UI).
- **Backend**: FastAPI, LangGraph (оркестрация агента), SQLAlchemy.
- **Хранилище**:
  - **Qdrant**: Векторная база данных для семантического поиска.
  - **PostgreSQL**: Хранение данных пользователей и истории сессий.
  - **Redis**: Кэширование и управление состоянием.
- **LLM**: Поддержка Z.ai (GLM-4), OpenRouter, OpenAI и Mistral.
- **Развертывание**: Docker Compose, внешние сети и тома для изоляции данных.

## 📋 Примеры использования

### 🧠 Обучение и теория
1. **"Объясни принцип работы градиентного бустинга простыми словами"**
   → Агент использует RAG для поиска в Учебнике Яндекса и формирует адаптивный ответ с формулами KaTeX.

2. **"Какие основные метрики используются в задачах ранжирования?"**
   → Получение структурированного ответа с разбором MRR, MAP и NDCG на основе верифицированных источников.

### 🧩 Проверка знаний (Квизы)
3. **"Проверь мои знания по теме Convolutional Neural Networks"**
   → Генератор тестов создает динамический квиз, оценивает ваши ответы и дает подробную обратную связь.

4. **"Запусти экзамен по основам классического машинного обучения"**
   → Формирование полноценного проверочного теста по широкому кругу тем из базы знаний.

### 💻 Алгоритмы и практика
5. **"Реши задачу на поиск кратчайшего пути в графе (Dijkstra)"**
   → Использование AlgoLab для написания, тестирования и анализа сложности алгоритма в реальном времени.

## 💡 Уникальные преимущества

**Это не просто RAG-чат, а интеллектуальный компаньон для профессионального роста**, который:
- Знает **глобальные знания** (учебник Яндекса)
- Готовит **к собеседованиям по теории ML и DL**
- Готовит **к собеседованиям по по алгоритмам с практикой написания кода и его тестирования в тест системе**

## 📚 Модульная структура

Проект состоит из независимых микросервисов, взаимодействующих через API и WebSocket:

- **[Agent Service](./agent_service)** — Мозг системы. Управляет логикой диалога и инструментами.
- **[RAG Service](./rag)** — База знаний. Реализует поиск по учебным материалам.
- **[Test Generator](./test_generator)** — Экзаменатор. Создает и проверяет тесты.
- **[User Service](./user_service)** — Профиль. Хранит настройки и историю прогресса.
- **[Web UI Service](./web_ui_service)** — Лицо. Обеспечивает взаимодействие пользователя с системой.

## 🚀 Развертывание

### 0. Подготовка (Клонирование и субмодули)

Перед началом работы необходимо склонировать репозиторий и инициализировать все вложенные модули:

```bash
# Клонирование основного репозитория
git clone https://github.com/lifelong-learning-assisttant/lifelong_learning_assistant.git
cd lifelong_learning_assistant

# Инициализация и обновление всех субмодулей
git submodule update --init --recursive

# Создание файлов окружения (.env) на основе примеров
# Необходимо выполнить для каждого сервиса:
cp agent_service/.env_example agent_service/.env
cp rag/.env.example rag/.env
cp test_generator/.env.example test_generator/.env
cp user_service/.env.example user_service/.env

# После копирования обязательно откройте .env файлы и заполните необходимые API ключи и настройки.
```

### 1. Развертывание на новом сервере (Bootstrap)

Если вы разворачиваете систему на новом сервере "с нуля", необходимо выполнить первичную инициализацию (создание сетей, томов и загрузку базы знаний):

```bash
# Сделать скрипт исполняемым
chmod +x init-new-server.sh

# Запустить инициализацию
./init-new-server.sh
```

**Важно:** Если вы планируете использовать PROD окружение, перед запуском убедитесь, что вы авторизованы в GitHub Container Registry:

```bash
echo $GITHUB_TOKEN | docker login ghcr.io -u USERNAME --password-stdin
```

Скрипт выполнит следующие действия:
1. Создаст внешние Docker-сети (`rag_rag_network`, `test_generator_default` и др.).
2. Создаст Docker-томы для хранения данных.
3. Инициализирует базу знаний RAG (скачивание и импорт бэкапов).
4. Инициализирует User Service (применение миграций и создание тестового пользователя).

Тестовый пользователь:
- логин `test_user`
- пароль `test_password`

После успешного завершения можно переходить к запуску в DEV или PROD режиме.

### 2. DEV окружение

Для запуска системы в режиме разработки (локальная сборка, горячая перезагрузка кода):

```bash
# Запуск всех сервисов
./start-dev.sh

# Остановка всех сервисов
./stop-dev.sh
```

### 3. PROD окружение

Для запуска системы в продакшн-режиме (использование стабильных образов из GHCR):

```bash
# Сборка всех Docker образов (опционально, если нужно обновить)
./build-prod.sh

# Публикация образов в GHCR (требуется авторизация)
./push-prod.sh

# Запуск всех сервисов
./start-prod.sh

# Остановка всех сервисов
./stop-prod.sh
```

Подробнее о развертывании и обновлении: [Deployment Documentation](docs/deployment/update-prod.md)
